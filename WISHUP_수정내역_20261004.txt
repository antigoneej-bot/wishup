WishUp 코드 점검·수정 결과 — 2026-10-04
버전: 1.0.4+6

1. 수정 사항
- 습관의 연속 달성 일수를 실제 완료 날짜로 계산합니다. 빠진 날짜가 있으면 연속 기록이 끊어지며, 당일 취소와 앱 재시작에도 다시 계산합니다.
- 목표에 새 세부 단계를 추가하면 달성률도 즉시 다시 계산합니다.
- 목표 삭제 직후 상세 화면이 사라진 목표를 조회하다 오류를 내던 경로를 방어했습니다.
- 백업의 버전, 필수 목록, 중복 ID, 모델 데이터, 설정 자료형, 이미지 데이터 등을 기존 기록 삭제 전에 검증합니다.
- 복원 중 저장 오류가 나면 기존 기록 복구를 시도합니다. 여러 Hive 박스에 걸친 작업이므로 전원 차단까지 보장하는 원자적 복원은 아닙니다.
- 백업으로 프리미엄 권한을 변경하지 못하게 했습니다. 현재 기기의 권한은 보존하고 스토어 조회로 동기화합니다.
- 새 백업(v2)에 현재 읽을 수 있는 비전보드 사진의 실제 데이터를 포함합니다. 사진 선택 시 앱 저장 공간에 복사하여 임시 파일 정리로 사진이 사라지는 위험을 줄였습니다.
- 기존 v1 백업도 읽을 수 있습니다. v1에는 사진 원본이 없으므로 다른 기기에서 사진을 복구할 수는 없습니다. 이미 사라진 원본도 복구할 수 없습니다.
- 복원 후 이전 예약 알림을 취소하고 복원된 기록에 따라 다시 예약합니다.
- 설정 화면에서 내보내기·복원 도중 화면을 나갈 때 setState가 호출되는 문제와 복원 실패 시 계속 처리 중으로 남는 문제를 수정했습니다.
- 결제 조회 실패를 구독 만료와 구분해, 통신 실패만으로 기존 유료 이용 권한을 해제하지 않습니다.
- Android/iOS RevenueCat 키를 분리하고 dart-define으로 주입하도록 변경했습니다. 키가 없으면 결제는 준비 중으로 동작합니다.
- Android 예약 알림 수신기·재부팅 수신기 및 필요한 권한을 보완했습니다. 알림 권한 거부 시 설정이 켜진 것으로 저장하지 않습니다.
- iOS 사진 보관함 사용 목적 문구를 추가했습니다.
- 오디오 로드/조작 실패 안내와 재시도, 완료 후 재재생 설정, 중복 조작 방어, 작은 화면 스크롤을 추가했습니다.

2. 확인 결과
- Flutter 3.38.10 / Dart 3.10.9 환경.
- flutter analyze --no-pub: No issues found.
- flutter test --no-pub: 90개 통과.
- 오디오 목록 8개와 실제 파일 경로 일치 확인.
- 원래 테스트 중 연속 달성의 숫자만 임의로 변경하던 테스트를 실제 완료 날짜 기반으로 수정했습니다.
- 신규 회귀 테스트: 날짜 단절·중복, 손상 백업에서 기존 기록 보존, 중복 ID, 설정 형식 오류, 유료 권한 보호, v1 백업, 이미지 데이터 오류, 세부 단계 추가 시 달성률.
- 네이티브 APK/AAB 및 iOS 빌드·실기기 검증은 수행하지 않았습니다. 자동 테스트 통과는 스토어 출시 검증 완료를 의미하지 않습니다.

3. 출시 전 남은 항목
- 실제 RevenueCat 프로젝트, 상품, entitlement, offering을 연결하고 스토어 구매·복원을 테스트해야 합니다.
  Android: --dart-define=REVENUECAT_ANDROID_API_KEY=실제공개SDK키
  iOS: --dart-define=REVENUECAT_IOS_API_KEY=실제공개SDK키
- 요금 화면은 고정 예시 가격을 사용합니다. 실제 스토어 현지 가격과 일치시키는 작업이 남았습니다.
- Android 서명 설정 파일이 없으면 현재 Gradle 설정은 debug 서명으로 폴백합니다. 정식 업로드 전에 본인 릴리스 키를 설정해야 합니다.
- iOS 프로젝트에는 com.example 계열 설정 등이 남아 있을 수 있어 Bundle ID, 개발 팀, 서명 설정을 Xcode에서 확인해야 합니다.
- 알림 시간대는 기존 한국(Asia/Seoul) 기준입니다. 해외 사용자를 지원하려면 기기 시간대 연동이 필요합니다.
- 오디오 음원 내용·배경음·속도 자체는 이번 수정에 포함되지 않습니다. 실제 휴대폰에서 듣고 판단해야 합니다.
- 포인트는 현재 저장된 활동에서 계산되므로 기록 삭제 시 내려갑니다. 코드의 '절대 감소하지 않음' 주석과 실제 동작이 다릅니다. 영구 누적형으로 바꾸려면 정책과 별도 누적 저장이 필요합니다.
- 앱을 켠 채 날짜가 넘어가는 경우 모든 화면의 자동 갱신은 별도 보완 대상입니다.
- 구매/알림/사진 공유 등의 네이티브 기능, 백업 사진의 다른 기기 복원은 실기기 확인이 필요합니다.

4. 휴대폰 확인 순서
① 기존 기록이 있는 기기에서는 먼저 백업한 뒤 업데이트합니다.
② 목표 추가 → 세부 단계 완료 → 새 단계 추가 → 삭제를 확인합니다.
③ 습관 완료/취소 후 앱 재시작 시 연속 기록을 확인합니다.
④ 사진을 넣고 백업 → 복원하여 글과 사진이 모두 나타나는지 확인합니다.
⑤ 알림 권한 허용/거부, 예약 알림 수신, 재부팅 이후 알림을 확인합니다.
⑥ 오디오 재생/일시정지/이동/끝까지 재생 후 다시 재생/뒤로 나가기 시 소리 종료를 확인합니다.
⑦ RevenueCat과 스토어를 설정한 뒤 테스트 계정으로 구매·취소·복원·통신 끊김을 확인합니다.
